# 第一版验收记录

日期：2026-10-06。系统：当前 Windows x64 工作机。Electron 44.5.1，React 19.2.7，Vite 8.3.3，Forge 8.0.1，better-sqlite3 13.0.3。

## 自动验证

- `npm test`：31/31 通过，包括原项目 20 项，以及保存失败事务回滚、版本冲突、历史恢复、JSON 备份往返、秘密排除、重开数据库、串行保存、保存失败重试、迟到响应、配置读取期间单任务、旧输入拒收、超限不截断和固定连接测试。
- `npm run test:desktop`：11 组实际 Electron 窗口流程通过。创建书籍章节、自动保存、safeStorage 加密、受限 preload、窄窗布局、多轮复核、保存失败阻止导航和退出、重检失败保留记录、取消隔离迟到结果、单章导入和版本恢复、三个导出及副本导入、正常退出立即保存、重启恢复且不自动请求。
- UI 截图已人工检查，保留纸色、红色批注；1050 px 窗口问题区位于编辑区下方。
- 打包所用 Electron ZIP 与 npm Electron 包内置 SHA-256 相符，SQLite 使用随包 Node-API 原生库。

## 真实模型

使用现有环境的 DeepSeek 配置尝试了一次固定短文本连接测试，接口返回鉴权失败。测试没有重试，也未继续发起章节检查。需要在设置中填写有效密钥后完成真实 API 验收；这项不能标记为通过。

## 安装环境边界

- Forge 已生成 1.0.1 Squirrel Windows x64 安装包、完整更新包及 ZIP。Squirrel 的旧版资源编辑工具不能读取中文路径，工程通过 `build/ascii-squirrel.cjs` 在生成的临时 ASCII 目录中制作安装器，再复制回项目目录；运行时校验未关闭。
- 实际运行 1.0.0 安装包，退出码 0，程序安装到当前用户 `%LOCALAPPDATA%\Duidu\app-1.0.0`。实际安装程序通过启动、SQLite 写入、重复启动单实例及重启恢复。
- 实际运行 1.0.1 安装包升级，退出码 0。启动安装后的 1.0.1，原 1.0.0 创建的独立验收数据目录仍保留原稿，再次通过单实例、保存和重启恢复。
- 两版测试程序的 PATH 只保留 Windows 系统目录，移除了外部 Node.js；原生 SQLite 依然正常。包内检查确认不包含 `.env`、测试数据、输出截图及缓存，也不暴露测试控制接口。
- 当前机器安装有 Node.js，不能声称已在全新、未安装 Node.js 的 Windows 虚拟机验收。这是剩余环境验收项。

最终交付版本为 1.0.1，源码 `package.json` 与安装程序的实际运行版本一致。数据目录与安装目录分离；较新数据库拒绝降级打开的自动测试已通过。此个人使用安装包没有 Authenticode 代码签名。
